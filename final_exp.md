# 🛡️ Nexus — AI-Powered Self-Healing OS Resource Guardian
> **Complete Project Explanation, Features, Execution Walkthrough & Machine Learning Guide**

---

## 📋 1. Problem Statement

Modern operating systems execute hundreds of background processes simultaneously. However, traditional system management approaches suffer from major limitations:

1. **Reactive Operating Tools:** Standard tools like Windows Task Manager or macOS Activity Monitor are **purely reactive**. Users open them *after* the PC freezes, stutters, or crashes.
2. **Runaway CPU Spikes & Infinite Loops:** Stuck application threads or runaway background scripts consume 100% of available CPU cores, causing system lag and rendering interactive user interfaces unresponsive.
3. **Memory Leaks:** Applications accumulate RAM over time without releasing it, degrading OS performance and eventually triggering system crashes or Out-Of-Memory (OOM) errors.
4. **Risk of Fatal User Errors:** Non-technical users attempting to fix a lagging PC often crash their system by accidentally terminating critical system services (e.g., `explorer.exe`, `svchost.exe`, or `lsass.exe`).

## 💡 2. The Solution: Nexus Resource Guardian

**Nexus** is an autonomous, AI-driven operating system resource guardian. It operates on a **continuous 5-step self-healing loop every 2 seconds**:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        NEXUS AUTONOMOUS LOOP                           │
├─────────────┬─────────────┬─────────────┬──────────────┬───────────────┤
│  1. SENSE   │  2. THINK   │  3. DECIDE  │   4. ACT     │   5. RECORD   │
│  psutil     │ Isolation   │ Decision    │ Action       │ SQLite Audit  │
│  Kernel     │ Forest +    │ Engine +    │ Executor     │ Log & Live    │
│  Telemetry  │ Forecasting │ Guardrails  │ (Live/Sim)   │ WebSockets    │
└─────────────┴─────────────┴─────────────┴──────────────┴───────────────┘
```

1. **Sense:** Continuously monitors CPU, RAM, Disk, Network, and the top 100 running processes using native OS APIs (`psutil`).
2. **Think:** Employs an **Isolation Forest ML algorithm** to detect anomalies and **Linear Regression Forecasting** to predict resource exhaustion before crashes happen.
3. **Decide:** Evaluates process metrics against safety guardrails and system blacklists (preventing accidental termination of critical system files).
4. **Act:** Autonomously executes corrective healing actions (**Renice**, **Throttle**, **Suspend**, **Restart**, or **Kill**).
5. **Record:** Persists incident audit trails to SQLite database and broadcasts live updates to the dashboard via WebSockets.

## 🖥️ 3. Features Walkthrough by Menu

Nexus features a clean, glassmorphic web dashboard with 7 distinct pages:

### 📊 1. Dashboard
* **System Vitals Hero:** Real-time dynamic gauge charts for CPU Load, Memory (RAM), Disk Storage, and Network I/O transfer rates.
* **Predictive Warning Banner:** Highlights upcoming resource exhaustion risks detected by ML forecasting.
* **Active Incidents Stream:** Live stream of open anomalies and critical process events.
* **Recent Healing Actions:** Log showing recent autonomous corrective actions taken by Nexus.

### ⚙️ 2. Processes Menu
* **Filterable Process Table:** Displays running processes sorted by CPU and RAM usage with color-coded health badges (*Healthy*, *Warning*, *Critical*).
* **Process Drawer:** Clicking any process opens a detailed slide-over panel displaying command-line arguments, thread counts, RAM history sparklines, and **7 manual action buttons** (**Kill**, **Restart**, **Suspend**, **Resume**, **Throttle**, **Renice**, **Observe Only**).

### 🚨 3. Incidents Menu
* **Historical Audit Log:** Comprehensive history of all past anomalies, system incidents, and automated interventions.
* **AI Root Cause Summaries:** Plain-English explanations generated by Google Gemini LLM describing why an incident occurred and what action was taken.

### 🔮 4. Predictions Menu
* **Resource Exhaustion Projections:** Time-series charts visualizing memory growth trends.
* **Time-to-Breach Counter:** Predicts estimated minutes remaining before a process causes RAM exhaustion (e.g., *"RAM exhausted in ~12 min"*).

### ⏰ 5. Maintenance Menu
* **Scheduler:** Schedule maintenance windows (e.g., during database backups or system updates) where automated healing actions are suppressed to avoid interrupting planned workloads.

### 🛡️ 6. Policies Menu
* **Operating Mode Toggle:** Switch between **Simulation Mode** (log-only demo mode) and **Live Mode** (real OS action execution).
* **Threshold Sliders:** Adjust CPU, RAM, and Disk warning and critical threshold percentages.
* **Protected Blacklist & Permitted Whitelist:** Configure blacklisted processes that Nexus can never touch, and whitelisted processes allowed for automatic live healing.

### ⚙️ 7. Settings Menu
* **System Settings:** Configure database options, metrics polling interval (default 2s), and Google Gemini API key for AI summaries.

## 🧠 6. Everything About the Machine Learning (ML) Part Explained Simply

Nexus uses **3 distinct AI/ML techniques** to deliver intelligent, proactive system protection:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        NEXUS AI / ML TRIPLE ENGINE                     │
├──────────────────────────┬─────────────────────────┬───────────────────┤
│  1. ISOLATION FOREST     │  2. LINEAR REGRESSION   │  3. GEMINI LLM    │
│  Unsupervised Anomaly    │  Time-Series Resource   │  Plain-English    │
│  Detection               │  Exhaustion Forecast    │  Incident Summary │
└──────────────────────────┴─────────────────────────┴───────────────────┘
```

### 🌲 1. Isolation Forest (Unsupervised Anomaly Detection)

#### What is it?
Traditional monitoring tools use static rules (e.g., *"Alert if CPU > 90%"*). However, static rules fail to catch subtle leaks, like an application steadily consuming RAM over several hours without ever hitting 90% total system RAM.

**Isolation Forest** is an unsupervised machine learning algorithm designed specifically for anomaly detection.

#### How does it work in Nexus?
1. For every running process, Nexus extracts a feature vector: `[cpu_percent, memory_percent, memory_mb]`.
2. The algorithm randomly splits data points using decision trees. 
3. **Key Concept:** Normal processes behave similarly and take many splits to isolate. Anomalous processes (runaway loops, memory leaks) stand out quickly and require very few splits to isolate.
4. Nexus calculates an **Anomaly Score** between `-1.0` (Highly Anomalous) and `+1.0` (Normal).
5. If the anomaly score drops below the threshold, Nexus identifies the process as anomalous **even if total system memory threshold hasn't been breached yet**.

---

### 📈 2. Time-Series Linear Regression (Resource Exhaustion Forecasting)

#### What is it?
Forecasting answers the critical question: *"At the current rate of memory growth, how many minutes until this process crashes the system?"*

#### How does it work in Nexus?
1. Nexus maintains a rolling window history of memory usage (`memory_mb`) for every active process over time.
2. It fits a **Linear Regression model** ($y = mx + c$) to calculate the growth velocity ($m = \text{MB/minute}$).
3. It projects the trajectory forward against a threshold (e.g., 2048 MB limit per process or total RAM capacity).
4. **Output:** Calculates `minutes_until_breach` (e.g., *"RAM exhausted in ~12 min"*).
5. If `minutes_until_breach <= 5 min`, Nexus triggers an early warning or proactive renice action **before the crash happens**.

---

### 🤖 3. Google Gemini API (LLM Incident Summarizer)

#### What is it?
Raw telemetry data (e.g., `PID 8384 CPU 99.8% RSS 154MB score -0.42`) is difficult for human operators to quickly interpret.

#### How does it work in Nexus?
1. When an incident is triggered, Nexus sends the raw metric context to the **Google Gemini Pro LLM API**.
2. Gemini translates the technical incident into a structured JSON response containing:
   * **Plain-English Summary:** *"Process python.exe (PID 8384) experienced a sudden CPU saturation loop contending with interactive system threads. Nexus automatically lowered its priority to Below Normal."*
   * **Formatted Slack Alert:** Ready-to-send notification formatted for DevOps/IT Slack channels.
